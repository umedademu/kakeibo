# データ保管

## 保管先

CloudflareのD1データベースを使用します。

- データベース名: `kakeibo-db`
- 作成日: 2026年9月3日
- 保存場所: Cloudflareによる自動配置

## 保存する内容

- 財布、PayPay、PayPay銀行、FX口座の現在残高
- 残高を変更した日時と変更後の金額
- 毎日午前4時に確定する日別残高
- 固定費の項目名、金額、毎月の支払日、登録日時、更新日時
- 収入の摘要、金額、毎月の着金日、反映方法、登録日時、更新日時
- 借金の摘要、金額、登録日時、更新日時

日別残高は「日付と項目」の組み合わせを1件だけ保存し、定期処理が再実行されても重複しないようにします。

保存後に誤りが判明した日別残高は、対象の日付と項目を限定して訂正します。2026年9月4日に、2026年9月3日分の貯玉を24,549円減額しました。

総資産は別の残高として保存せず、画面を表示するときに5項目の現在残高を合計します。

直近30日の資産推移も別の集計結果として保存せず、日別残高を読み込むときに5項目を日付ごとに合計します。

未来30日の予測結果も保存しません。画面を表示するときの現在残高、収入、固定費から、その都度計算します。

固定費は1項目につき1件として保存します。新規追加と編集はVercel上のアプリからCloudflare Workerを経由して行い、登録済みの内容はパソコンとスマートフォンで共有します。

収入も1項目につき1件として保存します。反映方法は「一括」または「日割り」として項目ごとに保存します。新規追加と編集は固定費と同じ経路で行い、着金日順の一覧と合計額を各端末で共有します。

借金も1項目につき1件として保存します。摘要と金額の新規追加と編集はVercel上のアプリからCloudflare Workerを経由して行い、登録順の一覧と合計額を各端末で共有します。

## 接続方法

Vercel上のアプリからCloudflare Workerを経由してD1へ読み書きします。VercelとWorkerの間は、両方に登録した秘密の文字列で保護します。

ブラウザにはD1の接続情報や秘密の文字列を渡しません。

## 日別残高の確定

Cloudflareの定期処理を毎日19時（世界標準時）に実行します。これは日本時間の翌日午前4時に相当します。

その時点の最新残高を、日本時間で見た前日の日別残高として保存します。財布、PayPay、PayPay銀行の残高に変更がない場合も、同じ金額を保存します。

貯玉の現在額は家計簿用のデータベースへ複製せず、画面表示と未来予測の計算時に、収支管理アプリのCloudflare Workerから「全店舗合計の貯玉」を円単位で直接取得します。画面を開いている間は1分ごとに取得します。取得に失敗した場合、画面には直近の日別記録を代わりに表示します。

午前4時の定期処理では、収支管理アプリから取得できた最新の貯玉だけを前日分の日別残高へ保存します。取得に失敗した場合は古い貯玉を前日分として保存せず、ほかの4項目だけを保存します。5項目がそろっていない日の合計は、過去の資産推移へ表示しません。

収支管理アプリとの通信には、Cloudflare内の専用接続と、両方のCloudflare Workerだけが保持する秘密情報を使用します。ブラウザにはこの情報を渡しません。

FX口座については、パソコン上のMT5から日本時間の毎正時に、含み益・含み損を含むドル建て有効証拠金とドル円レートを受信します。ただし、午前4時分は午前3時59分に置き換えます。円換算後の金額で現在残高を更新し、換算に使った元のドル建て有効証拠金、レート、銘柄名、取得日時も保存します。

午前3時59分の取得結果を、午前4時に行う前日分の日別記録へ反映します。パソコンまたはMT5を利用できない場合は、その時刻の取得を行わず、午前4時の日別残高にはCloudflareに最後に保存された金額を使用します。

## 端末間の共有

パソコンで財布、PayPay、PayPay銀行の残高を変更するとD1へ即時保存されます。スマートフォンでアプリを開いたときも同じD1から読み込むため、同じ金額が表示されます。

## 資産推移の取得

Vercel上のアプリからCloudflare Workerへ直近30日分を問い合わせます。Workerは日別残高の5項目を日付ごとに合計し、古い日付から順に返します。保存済みの日別記録だけを使用し、記録がない日付の金額は作りません。

未来30日分は、Cloudflareに保存された現在残高、収入、固定費を同時に読み込み、Vercel上のアプリで計算します。固定費と日割りの収入は、それぞれの日付が属する月の日数で割って毎日反映します。一括の収入は着金日に全額を反映し、その月に着金日が存在しない場合は月末に反映します。
